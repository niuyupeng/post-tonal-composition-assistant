\section{Reproducibility Statement}
\label{sec:reproducibility}

All bundled data are generated from source code and fixed seeds. No copyrighted post-1945 score is downloaded or required. The corrected processed corpus is stored as \path{data/processed/project2_v3_main.pt}, and its explicit split is summarized in \path{results/project2_v3_full_split_summary.json}.

On Windows, \path{scripts/smoke_project2.ps1} runs the isolated CPU verification workflow. The corrected CUDA pipeline is invoked with \path{scripts/run_project2_full_local.ps1 -Resume}. It verifies Python 3.10/3.11, CUDA availability, tests, memory thresholds, corpus counts, configuration hashes, checkpoint hashes, metric-row counts, MusicXML structure, requested measures, requested voices, tables, and expert-package files.

Training writes a best checkpoint and a resumable last checkpoint containing optimizer, scaler, random-number, and epoch state. If CUDA memory is exhausted, the runner reduces physical batch size and increases accumulation without changing the corpus. Every completed training summary records the best epoch, elapsed time, effective batch, OOM adjustment, data/configuration hashes, and measured peak process RAM and allocated VRAM.

Corrected aggregate outputs use the \path{project2_v3_} prefix until all gates pass. The runner then promotes them to the canonical \path{results/project2_metrics.csv}, \path{results/project2_constraints.csv}, \path{results/project2_generation_examples.json}, \path{paper/tables/project2_main_results.tex}, \path{paper/tables/project2_ablation_results.tex}, and \path{expert_eval/project2/} paths. This delayed promotion prevents smoke or partial runs from replacing final evidence.

The source repository is maintained at the location stated on the title page. Large processed tensors and checkpoints may be excluded from version control, so an archival release must include code, configs, hashes, result tables, and regeneration instructions.
